## Summary

Overall rating: **Critical issues.** The Apple design skill sets the rating from the severity tags (`SKILL.md > Step 4: Write the report`), and one Critical finding decides it: B1, a CSS-only focus-ring fix. With B1 fixed, the 7 High findings would still rate the build Needs work.

The design's thesis: a calm, iPhone-like utility that turns "find TB care" into a three-stop route, under one colour rule: red means TB, teal means care. It will be remembered by the teal route line that draws in through three numbered stops (chest X-ray, TB test, free TB medicines), echoed by the stop motif on each place page.

Privacy and the Check logic are the strongest parts: nothing is stored beyond a language choice, location is used only after a tap, and Check routing matches the content pack on every answer combination.

## Check routing (safety check)

**Result: match.** Two independent read-only comparisons checked `src/lib/check/flow.ts` and the CheckFlow island against the content pack's section 4 decision table and against the prototype `Check.dc.html`. Neither found a routing difference. (Q numbers in this section are the pack's Check questions, not PLAN's owner questions.)

- **Against the pack.** A Python transcription of the pack's rules was run over every answer combination: 215,197 of them, counting both adult answers to Q1 (myself, another adult) and every set of danger signs. Every combination routes the same way: any danger sign gives urgent; then A for any Q3 symptom, blood (Q3b) or an X-ray 'yes' (Q5); B for recent symptoms (Q4) with a high-risk factor; C for any risk factor; D otherwise. The high-risk flags match (every risk factor except smoking or alcohol and crowded living). A 200,000-walk random simulation (Back, change an answer, Back from a result) reached 399,721 result screens with 0 stale answers and 0 routing mismatches.
- **Against the prototype.** A condition-by-condition read plus an enumeration of 110,688 reachable non-urgent answer sets (one adult answer to Q1) found no disagreement for any input checked: all no, all yes, urgent with other answers, each child symptom, recent only, a path switch mid-flow, and Back then change. Results: adult A 99,840, B 2,292, C 2,310, D 6; child A 6,048, B 95, C 95, D 2. Doubling the adult counts gives the pack comparison's totals (A 205,728, B 4,679, C 4,715, D 14), so the two runs agree.
- **One deliberate difference from the pack's literal note rules.** No add-on notes show on the urgent screen. README:226 limits notes to results A to D and the prototype does the same, so the code follows the spec. The only note this hides is the child note, on all 31 child urgent combinations. The owner confirms it (O11).
- **Three questions about the pack itself.** The code follows the pack; only clinicians may change it (O11):
  1. Current symptoms with only a lower-risk factor give result C, titled 'No signs of TB right now', without the recent-symptoms note. Inputs: adult, Q3 none, Q3b no, Q4 yes, Q5 no, unsure or none, Q6 only smoking or alcohol and/or crowded living. That is 18 combinations (9 per adult answer). The same person with no risk factor gets D plus the note to get tested if it lasts 2 weeks.
  2. The HIV note asks the person to tell their HIV care provider about 'these symptoms', but it also shows on C, where they reported none: 2,352 of 4,715 C combinations.
  3. The child note ('bring the child to your health center or a pediatrician') shows under D's 'No signs of TB right now' in 2 child combinations.
- Also pack-literal: Q4 is still asked when Q3b = yes has already fixed result A (6,144 adult combinations). The answer feeds the card's 'Recent symptoms' row.
- Not run: the TypeScript itself (Vitest, Playwright). Equivalence rests on the transcriptions and the reads. Unit-test gaps on the child path are B43.

## Critical

#### B1. Focus ring clipped or invisible on full-width rows and on the map (Critical)
- **What:** the global ring is 3px Ink drawn 3px outside the element, but every `.group` has `overflow: hidden` and its rows fill it edge to edge. A link row at the bottom of a group keeps only its top edge. Where the row is the group's only child, no ring shows at all: the 'Save TB PH to your home screen' row on Place and on the Check result, the closed Methods summary on Data and Learn's closed narrow contents summary. Leaflet makes the map container a Tab stop inside `.map-frame { overflow: hidden }`, so the focused map shows nothing.
- **Why:** WCAG 2.4.7; README:40 (a visible 3px focus ring everywhere) and README:116 (choice rows already draw it inside); `focus-and-selection.md > Tablet (iPadOS)` (a parent view must not clip the focus effect); SOT 'Hover states' row (equivalent focus-visible states).
- **Fix:** CSS only, focus state only. `outline-offset: -3px` on `.link-row`, `.install-row`, the Data Methods summary and Learn's narrow contents summary when focus-visible. For the map, draw the ring on the frame: `.map-frame:has(> .map:focus-visible) { outline: var(--focus-ring); outline-offset: 3px }` (an inset ring would sit under Leaflet's panes). docs/copy-overrides.md:13 is the precedent.
- **Class:** builder fix. **Step:** now. **Also affects:** Place, Check result, Data (index rows, Methods), About (install link row), Learn (contents summary), Places map. Learn's by-numbers groups hold only inline links and are fine.

### High

#### B2. Text sizes are fixed in px, so the browser text-size setting enlarges only headings (High)
- **What:** the seven body tokens `--text-14` to `--text-20` are px and body is 18px; only the four heading clamps are rem. 151 of 167 font-size declarations resolve to px. At a 24px browser default the 390px H1 grows from 34px to 51px while body stays 18px, so the H1-to-body ratio goes from 1.89x to 2.83x. Breakpoints are px too. Separately, the Filipino 'Gamitin ang aking lokasyon' capsule (`.locate`, nowrap) is 282.7px wide against a 252.4px sheet content box at 320px. That is 30.3px too wide, and `.planner` clips it, so a page-width test can't see it.
- **Why:** `accessibility.md > Vision` (support larger text sizes); `typography.md > Supporting Dynamic Type` (layouts adapt to every size); `typography.md > Conveying hierarchy` (keep the relative hierarchy when people change text size; tab labels need not grow).
- **Fix:** redefine the `--text-*` tokens and the raw px sizes as `max(px, rem)` (e.g. `--text-18: max(18px, 1.125rem)`), so nothing moves at the default 16px root and D1 holds. Width media queries in em (1000px is 62.5em). Make the 92px footer spacer and Check's 84px sticky offset rem-based, or take them from B14. Tab-bar labels may stay px. Let `.locate` wrap inside its capsule (drop nowrap, keep min-height 48px). Owner question O28: opt the installed iPhone app into iOS Larger Text, which changes default rendering.
- **Class:** builder fix (plus O28). **Step:** now, before 13 (step 13's matrix doesn't test a larger root size). **Also affects:** every page; learn.css, data.css and check.css add more px breakpoints and fixed sizes (26px chevrons, 22px Call 911, 13px Place motif number).

#### B3. Check: 'Next' with no answer shows its error out of view (High)
- **What:** a failed Next only sets the error state. The `role="alert"` error renders after all the options, before the sticky Next bar, with no scroll or focus move. On the adult risk step at 390x844 (9 options) the error starts at about y=918px with no wrapping and about y=1,134px with the expected wraps, while visible content ends near y=682px: 236 to 452px below the fold. The error has no id, so the group's `aria-describedby` never points to it, and a second failed tap changes nothing and isn't announced again. The child symptoms step has the same problem.
- **Why:** README:224 (inline error, sticky Next) and README:307 (errors in role=alert); WCAG 3.3.1.
- **Fix:** after a failed Next, `error.scrollIntoView({ block: 'nearest' })` with no smooth scrolling (D21). `scroll-margin-bottom` of about 162px plus the bottom safe area below the desktop breakpoint, about 78px above it. Add `id="q-error"` to the group's `aria-describedby` while it shows, and re-mount the alert on a repeat failed tap. Copy, colour and position stay the same.
- **Class:** builder fix. **Step:** now. **Also affects:** Check only.

#### B5. Side safe areas are ignored in landscape (High)
- **What:** `viewport-fit=cover` is set but `env()` is used only for the bottom inset. In iPhone landscape (844 to 956px wide) the 4vw side padding is 33.8 to 38.2px and the header and footer's 5vw is 42.2 to 47.8px, against side insets of about 47px (notch) to 59px (Dynamic Island). Backgrounds stay full-bleed; portrait and desktop render the same.
- **Class:** builder fix. **Step:** now; one WebKit 844x390 screenshot at 13. WebKit doesn't emulate insets, so verify on a real iPhone. **Also affects:** every page.

### Medium

#### B8. Focus is left behind by 'Show more' and dropped by every 'Try again' (Medium)
- **What:** 'Show more centers (N left)' inserts up to 20 rows before the button, which keeps focus. The aria-live count is the total, so nothing is announced. With the 93-row sample, taps 1 to 3 leave focus on the button up to 60 Tab stops past the new rows, and tap 4 unmounts it, so focus falls to body. Each 'Try again' (Home list, Places list, Places map) unmounts as loading restarts and drops focus to body.

- **Fix:** after the limit grows, focus the first new row's name link (remember the old limit). Before a 'Try again' unmounts, focus the loading line (tabindex -1), then the field (Home), the count heading (Places list) or the map frame. Nothing visible changes.

## What works

Keep these; they are the build's strengths.
- **Privacy by construction.** The only storage is the language choice (localStorage 'tbph-lang') and a one-navigation scroll anchor deleted on read. There are no cookies, analytics, sendBeacon or console logging. Location is asked for only on a tap, held in memory and never put in a URL (checked in home.spec.ts and places.spec.ts). Place links carry only id and stop (Q4a), and Google Maps directions carry only the destination.
- **Check keeps answers in memory.** It adds no history entries, and check.spec.ts asserts same-origin requests only, no answer words in any URL or body, and unchanged storage, IndexedDB and caches. The saved image is drawn locally, named tbph-summary.png, and its object URL is revoked.
- **Check routing and flow.** Routing matches the pack and the prototype on every combination; each step focuses its H1 instantly; Back from the urgent screen returns to the danger question. The urgent screen measures white on Film 17.65:1, red on the white Call 911 capsule 5.83:1 and its translucent buttons 10.78:1. Printing outputs only the card.
- **Security.** A hashed CSP with no unsafe-inline, no data: and OSM tiles as the only outside image host; every e2e test fails on a CSP violation, console error or page error. There is no innerHTML on data, map popups use textContent, and URL parameters are whitelisted (svc, need, loc, near up to 100 characters, stop 1 to 3).
- **Performance by design.** JS per page is estimated at 19 to 44KB gzip against a 60KB budget (Home about 26, Places 28, Check 23, Place 19, Data 44; Learn, About, Install and 404 at 4KB or less). Leaflet (42.4KB gzip) loads only when Map is chosen. Fonts are self-hosted, preloaded and paired with metric-matched fallbacks. The stop motif is set before paint.
- **Data page accessibility.** Every chart is an SVG with an aria-label and a 'View as table' ARIA table in a labelled, focusable region. Toggles use aria-pressed in labelled groups, with a select below 720px. Claim deep links focus a row with a visible ring. The dot story's beats are real text, with hidden data lists for beats 5 and 6.
- **Structure.** One H1 per page and a correct heading order on Place, Check, Learn, Data, About and Install; native radios and checkboxes on Check; Install's steps are reordered in the DOM, so reading order matches what's shown; About's tel: links are 44px, with names that contain the visible number.
- **Measured contrast.** Muted #56626A on white 6.27:1, TB red on white 5.83:1 and on Canvas 5.24:1, Teal deep on Canvas 7.71:1, white bold text on teal 6.19:1.
- **Tests on what ships.** E2E runs against the built dist/ through a server that mimics the host (slashless files, 308s, the nearest 404.html), in Chromium and WebKit, under the real CSP. Every build ends with an internal link and link-language crawl, and launch-check blocks on sample data, placeholders and owner strings.
- **Phone basics.** Inputs are 18 to 19px, so iOS doesn't zoom, and zoom stays allowed. The bottom safe area is handled on the tab bar, the footer spacer, the sheet and Check's Next. Scroll listeners are passive and rAF-throttled.
- **Robust with real data.** Long names, multi-number phones and long Filipino labels wrap; the saved image wraps text by measurement.
