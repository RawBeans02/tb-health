## The independent review

An independent review of the launch build (8 Nov) checked the data, search, the build without Check, the tests and the docs. What it confirmed, and where each was fixed:
- clinic pins in the wrong town (for example Santiago City's three clinics pinned in Iligan, about 980 km away) and 22 clinics with no pin: f05b908;
- Davao Region numbers printed without their area code's 0, so their Call buttons couldn't connect: f05b908 (data) and 8b5e1d2, 83845f0 (code);
- typed province names that planned from a same-named town hundreds of km away ("Isabela": Isabela, Basilan, about 1,100 km): e992bb1. A first fix (bd1dc9c) was rejected by its own review, as landmark text such as "Baguio General Hospital" then matched nothing;
- Check's code still built and precached, and its strings in the page data, in a build without Check: 297623b, 6860e80;
- a test server left running on the shared port, `test:no-check` leaving the full list in `dist/`, Lighthouse's default list including /check, about.spec's three privacy rows: 8b5e1d2;
- the Sakay.ph button copying the clinic's name: baf7c3e.

Each fix was reviewed again by a separate agent before it was merged.

The search took three more rounds. A review of e992bb1 found that a barangay named like a town elsewhere planned from that town ("Bagumbayan, Taguig City" from Sultan Kudarat, 964 km): fixed in 3ad2bf0. A re-review of 3ad2bf0 by four reviewers, each checked by a skeptic, confirmed 27 issues ("Magsaysay, Quezon, Palawan", "San Fernando City, Pampanga", "…, Rizal", "Cubao, QC", "Cubao, Metro Manila" and others). Their tested fixes were merged in two rounds against every family the reviews measured, each round checked again by fresh skeptics: d9fb27e. On 1,967,829 generated and listed inputs, right within each family's limit: d5a9d05 1,681,125, 3ad2bf0 1,740,505, d9fb27e 1,856,429.
